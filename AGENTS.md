# AGENTS.md

## Commands

```bash
bun test                          # tests
bun run typecheck                 # tsc --noEmit (sky, sst-env.d.ts included)
bun run lint                      # oxlint (config in .oxlintrc.json)
bun run dev                       # local Cloudflare simulation (via `bun run dev`)
bun run deploy                    # deploy to Cloudflare (via `bun run deploy`)
bun run build                     # build SST app (note: NOT the frontend build)

# Frontend (separate package, must be built before SST serves new assets)
( cd packages/web && bun run build )   # vite build → packages/web/dist

# Snapshot generation → snapshot.ndjson (top PyPI packages by 30-day downloads)
bun scripts/build-snapshot.ts

# Apply database migrations (schema changes only; does not seed data)
bun run db:migrate

# Seed package data explicitly
bun run db:seed:local
bun run db:seed:bigquery
bun run db:seed:snapshot

# Backfill download counts from hugovk snapshot (after schema migration)
bun scripts/backfill-downloads.ts

# Tear down the local Postgres volume (nuclear option; requires re-seed after)
docker compose down -v
```

`sst-env.d.ts` is auto-generated by SST on `bun run dev` / `bun run build`. `bun run typecheck` includes it via `tsconfig.json` so `Resource.*` bindings resolve; if you change `sst.config.ts` resource names, re-run `bun run build` (or `bun run dev`) before typechecking.

## SST dev requirements

`bun run dev` provisions `pypi.pro` on Cloudflare **and** automatically starts the local Postgres + Neon HTTP proxy via `docker compose up --wait` (see `docker-compose.yml`). The side-effect is gated on `DATABASE_URL` host being `db.localtest.me`, so `bun run deploy` against a real Neon connection string skips Docker entirely.

Prerequisites:

1. Docker (or OrbStack) running locally
2. `CLOUDFLARE_API_TOKEN` env var set, or SST prompts for interactive login on first run
3. `pypi.pro` added to your Cloudflare account with DNS control (only needed for `bun run deploy`)
4. First run creates `.sst/` state dir
5. `.env` with `DATABASE_URL=postgres://postgres:postgres@db.localtest.me:5432/main` (copy `.env.example`)

After the first `bun run dev`, the database may be empty. Migrations only create or update the schema; seed package data explicitly with `bun run db:seed:local`, `bun run db:seed:bigquery`, or `bun run db:seed:snapshot`.

## Local dev data flow

`bun run dev` → `docker compose up --wait` → Postgres 17 on `:5432` + `local-neon-http-proxy` on `:4444`. The proxy translates the `@neondatabase/serverless` HTTP fetch protocol (`POST :4444/sql`) into real Postgres wire protocol, so the same `neon(connectionString)` client works against local Postgres and against real Neon in production without code changes.

`db.localtest.me` is a public DNS name that always resolves to `127.0.0.1` (wildcard `*.localtest.me`), avoiding the need to edit `/etc/hosts`. If you need to work fully offline, add `127.0.0.1 db.localtest.me` to `/etc/hosts`.

## Neon Postgres database

Storage is **Neon Postgres** (serverless) in production, **local Postgres 17 via the Neon HTTP proxy** in dev. The connection string lives in `.env` as `DATABASE_URL` and is propagated to every Worker/Cron/Consumer via `environment` in `sst.config.ts` (read from `process.env` at config time). No SST-managed resource is created — Neon projects / local Docker are provisioned out-of-band and referenced by URL.

## Architecture

Infrastructure: Worker (search API + static assets) + Cron (daily BigQuery refresh). Storage is Neon Postgres (external). Resources are composed through `infra/app.ts`.

Worker entry `src/worker.ts` routes:

- `GET  /api/search?q=` — search
- `GET  /search` → redirects to `/?q=...`

Search behavior (`src/search.ts`):

- Single-query tiered ranking:
  1. Exact name match (tier 0)
  2. Prefix `LIKE 'q%'` match (tier 1) — uses btree `text_pattern_ops` index
  3. Trigram fuzzy name match (tier 2) — uses GIN `gin_trgm_ops` index with k-NN `<->` ordering
  4. Full-text match over name+summary+keywords (tier 3) — uses GIN `search_tsv` index
- Tiers 2-3 are disabled for queries shorter than 3 characters
- Within tiers, results sort by: tier → relevance score → `ln(downloads_4w+1)` → name
- Results capped at 20, duplicates deduplicated across tiers (lowest tier wins)

Data source for snapshots: `hugovk/top-pypi-packages` 30-day JSON, enriched via per-package `pypi.org/pypi/<name>/json`.

## Quirks

- `packages/web/dist` is the static assets dir, but `sst.config.ts` references it via an absolute path (`/root/pypipro/packages/web/dist`) — this is the Cloudflare build environment path, not local. Don't "fix" it to a relative path without testing `bun run deploy`.
- Worker uses `compatibility date 2026-06-01` with `nodejs_compat` flag.
- `pypi.db` at repo root is gitignored local scratch (legacy Miniflare/D1 local), not committed.
- Frontend is vanilla TS + Vite (no framework). Rebuild `packages/web` before deploying to pick up UI changes.
